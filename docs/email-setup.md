# ตั้งค่าอีเมลแจ้งเตือนแอดมิน

ระบบบันทึกการแจ้งเตือนเมื่อมีสมาชิกสมัครใหม่ แล้วลองส่งอีเมลหลังตอบกลับฟอร์ม โดยแอดมินไม่ต้องเปิดเว็บค้างไว้ หากส่งไม่สำเร็จจะเก็บสถานะและลองใหม่ผ่าน Cron รายวัน หรือปุ่ม “ลองส่งรายการค้างใหม่” ในหน้าแจ้งเตือน การตอบรับจาก SMTP หมายถึงผู้ให้บริการรับข้อความแล้ว ยังไม่รับประกันว่าเข้ากล่องหลัก

## 1. เตรียมบัญชีผู้ส่ง

สำหรับใช้งานของหน่วยงาน ขอข้อมูลจากผู้ดูแลอีเมลมหาวิทยาลัย: SMTP hostname, port, TLS/STARTTLS, username, รหัสสำหรับแอป และอีเมลผู้ส่งที่ได้รับอนุญาต บัญชีองค์กรบางแห่งปิด SMTP password authentication ต้องให้ผู้ดูแลจัดช่องทางที่รองรับก่อน

หากจะใช้ Gmail ที่อนุญาต App Password:

1. เปิด [การยืนยันตัวตนสองขั้นตอน](https://myaccount.google.com/security)
2. เปิด [App Passwords](https://myaccount.google.com/apppasswords) สร้างรายการชื่อ `Management Skills` แล้วเก็บรหัสที่ได้ไว้ส่วนตัว ไม่ใช้รหัสผ่านเข้าสู่ Gmail ตามปกติ
3. หากไม่มีเมนู App Passwords บัญชีมหาวิทยาลัยอาจมีข้อจำกัด ให้ติดต่อผู้ดูแล หรือใช้ SMTP ของหน่วยงาน ดู [ข้อกำหนดของ Google](https://support.google.com/accounts/answer/185833)

## 2. เพิ่ม Environment Variables ใน Vercel

เปิด Project `management-skills` → Settings → Environment Variables เลือก Production แล้วเพิ่มค่าต่อไปนี้ ตัวอย่างทั้งหมดเป็น placeholder ต้องแทนด้วยข้อมูลจริง:

```dotenv
SMTP_URL="smtps://sender%40gmail.com:APP_PASSWORD@smtp.gmail.com:465"
MAIL_FROM="Finance Division <sender@gmail.com>"
APP_URL="https://management-skills.vercel.app"
```

- `SMTP_URL`: สำหรับ Gmail ใช้ App Password โดยไม่ใส่ช่องว่าง ค่าชื่อผู้ใช้และรหัสผ่านใน URL ต้องเข้ารหัสอักขระพิเศษ เช่น `@` เป็น `%40` ด้วย `encodeURIComponent` บนเครื่อง ห้ามใช้เว็บภายนอกเข้ารหัส secret
- `MAIL_FROM`: ต้องเป็นอีเมลที่ผู้ให้บริการยอมให้ส่งได้ โดยตัวอย่าง Gmail ใช้บัญชีเดียวกับ SMTP
- `APP_URL`: URL สาธารณะของเว็บ ใช้สร้างลิงก์เปิดหน้าบัญชีรออนุมัติในอีเมล
- หากหน่วยงานให้ port 587 ใช้ `smtp://ENCODED_USER:ENCODED_PASSWORD@SMTP_HOST:587/?requireTLS=true` เพื่อบังคับ STARTTLS ส่วน port 465 ใช้ `smtps://...:465` ดู [Nodemailer SMTP](https://nodemailer.com/smtp)

กด Save แล้วไป Deployments → deployment ล่าสุด → Redeploy เพื่อให้ค่ามีผล ไม่ต้องเปลี่ยนฐาน Neon หรือรัน seed ซ้ำ

สำหรับเครื่องพัฒนาใส่ใน `.env` แล้วเริ่ม `npm run dev` ใหม่ ส่วน `.env.production` เป็นไฟล์ส่วนตัวสำหรับตั้งค่าบนเครื่อง ไม่อัปโหลดเข้า Vercel ให้อัตโนมัติ อย่า commit ไฟล์เหล่านี้หรือส่งรหัสผ่านในแชต

## 3. กำหนดอีเมลผู้รับ

เข้าสู่ระบบเป็น admin → ทะเบียนและการตั้งค่า → บัญชีผู้ใช้ → เปิดบัญชีแอดมิน ใส่ “อีเมลสำหรับแจ้งเตือน ADMIN” แล้วกดบันทึก ทุกบัญชี ADMIN ที่ใช้งานอยู่ อนุมัติแล้ว และเชื่อมทะเบียนบุคลากร จะมีรายการแจ้งเตือนของตนเอง ผู้ส่งกับผู้รับเป็นคนละอีเมลได้

หลังบันทึก ระบบจะลองส่งรายการค้างของแอดมินคนนั้นใหม่ และมีปุ่ม “ทดสอบส่งอีเมล” พร้อมสถานะอีเมลล่าสุดแยกแต่ละบัญชี ต้องบันทึกอีเมลก่อนกดทดสอบ อีเมลผู้ส่งยังคงเป็นบัญชี SMTP กลางเดียวกัน ส่วนช่องอีเมล ADMIN เป็นผู้รับ ไม่ต้องสร้าง App Password ใหม่ให้ผู้รับแต่ละคน

## 4. ตรวจการทำงานจริง

1. สมัครบัญชีทดสอบผ่าน `/register` ด้วยตัวเอง แล้วเปิดหน้า “การแจ้งเตือน” ของแอดมิน
2. ตรวจว่ามีรายการสมาชิกใหม่ทั้งในระบบและอีเมล สถานะอีเมลต้องเป็น “ส่งแล้ว” จึงหมายถึง SMTP ตอบรับข้อความ ตรวจกล่องจดหมายและ Spam ด้วย
3. หากขึ้น “ส่งไม่สำเร็จ” อ่านสาเหตุใกล้รายการ ตรวจ SMTP และอีเมลผู้รับให้ครบ แล้วกด “ลองส่งรายการค้างใหม่”
4. การอนุมัติสมาชิกยังต้องทำโดยแอดมินที่ `/admin#accounts` ระบบไม่อนุมัติแทนเพราะส่งอีเมลได้

Cron รายวันต้องมี `CRON_SECRET` ใน Vercel ด้วย ส่วนสมาชิกใหม่จะลองส่งทันทีหลังสมัคร ไม่ต้องรอ Cron หากบัญชีได้รับอนุมัติไปแล้ว ระบบจะยกเลิกอีเมลรออนุมัติที่ยังค้างอยู่ การลองส่งอัตโนมัติจำกัด 10 ครั้งต่อรายการ หลังแก้การตั้งค่าแล้วปุ่มลองส่งใหม่จะเริ่มนับความพยายามใหม่ให้รายการที่ล้มเหลว

ขณะยังไม่มี SMTP ใช้งานได้เฉพาะข้อความแจ้งในระบบและคิวอีเมล ไม่ถือว่าได้ส่งอีเมลจริงแล้ว
