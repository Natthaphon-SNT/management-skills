# ใช้งานและเก็บข้อมูลเกิน 5 ปี

ระบบแบ่งข้อมูลตามปีงบประมาณ ไม่ได้จำกัดอายุไว้ 5 ปี การเพิ่มปีใหม่ไม่ลบรายงานปีก่อน ปัจจุบันรองรับปี พ.ศ. 2500–2700 ชุดทดสอบตรวจการเพิ่มอีก 6 ปีพร้อมอ่านรายงานปีเดิม และนโยบายลบอัตโนมัติปิดเป็นค่าเริ่มต้น

## การลบทะเบียนและบัญชี

แอดมินลบได้จากแต่ละรายการ ต้องใส่เหตุผลและพิมพ์ DELETE การลบนี้นำรายการออกจากหน้าจัดการ ปิดบัญชีและเซสชัน และเก็บแถวอ้างอิงไว้เพื่อรักษารายงานและประวัติเดิม ไม่ใช่การล้างข้อมูลส่วนบุคคลถาวร การลบทะเบียนจะปิดและนำบัญชีที่เชื่อมกันออกด้วย ส่วนการลบบัญชีอย่างเดียวไม่ลบทะเบียน

กู้คืนจาก “รายการที่ลบ” โดยกู้ทะเบียนก่อนบัญชี หลังคืนรายการยังปิดใช้งานอยู่ แอดมินต้องตรวจข้อมูลและเปิดใช้งานเอง รหัสบุคลากร ชื่อผู้ใช้ และอีเมลของรายการเดิมยังถูกสงวนไว้ ไม่ให้นำไปผูกเป็นคนอื่น ทะเบียนที่ลบแล้วไม่ถูกเพิ่มลงฐานปีใหม่ แต่รายงานและฐานปีเก่ายังอยู่ การลบรายงานหรือการลบทั้งปีเป็นคนละคำสั่งและมีเงื่อนไขแยกกัน

## ความจุและการดูแล

ระยะเวลาใช้งานจริงขึ้นกับจำนวนรายงาน ไฟล์แนบ สำเนา Excel และ ZIP สำรองที่สะสม ไม่ได้ขึ้นกับจำนวนปีอย่างเดียว แอปปัจจุบันเก็บไฟล์เหล่านี้ใน Postgres ตัวอย่าง 200 รายงานต่อปี มีไฟล์รายงานละ 1 MB เป็นเวลา 5 ปี จะมีไฟล์ประมาณ 1 GB โดยยังไม่รวมตาราง ดัชนี Excel และสำรอง

Neon ระบุ Free storage ปัจจุบัน 1 GB ต่อ project และไม่กำหนดระยะเวลาทดลอง แต่ต้องตรวจโควตาของโครงการที่เชื่อมผ่าน Vercel Marketplace ด้วย ดู [Neon pricing](https://neon.com/pricing) ส่วน Vercel Hobby มีขีดจำกัดการใช้งานและเงื่อนไข personal/non-commercial ดู [Vercel Hobby](https://vercel.com/docs/plans/hobby) เงื่อนไขและโควตาของผู้ให้บริการเปลี่ยนได้ จึงรับประกันว่าฟรีและเพียงพอครบ 5 ปีล่วงหน้าไม่ได้

สำหรับใช้งานหน่วยงานระยะยาว ให้ติดตามพื้นที่และปริมาณเรียกใช้ เก็บสำรองแยกจากฐานหลักและดาวน์โหลด ZIP ไว้ ทดสอบกู้คืนเป็นระยะ อัปเดต Node.js/Next.js/Prisma และ dependency ด้านความปลอดภัย และวางแผนเพิ่มพื้นที่หรือย้ายไฟล์ไป object storage เมื่อข้อมูลโต การสำรองไว้ในฐานเดียวกันอย่างเดียวไม่ป้องกันฐานหายทั้งโครงการ การย้ายที่เก็บหรืออัปเกรดแพ็กเกจไม่ได้ทำให้อัตโนมัติ

เก็บ source code รุ่นที่สร้างสำเนาและ package-lock.json ควบคู่กับ ZIP ด้วย เครื่องมือกู้คืนตรวจรุ่น schema ก่อนนำเข้าข้อมูล หากเป็นสำเนาก่อนปรับโครงสร้างฐาน ต้องกู้ด้วยรุ่นที่ตรงกับสำเนานั้นก่อน แล้วจึง migrate ไปโครงสร้างใหม่
